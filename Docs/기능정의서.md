> 작성일 2026-07-14 · 마감 2026-07-22

## 0. 이 문서의 범위

- **엔진:** Unity 6000.4.9f1, URP 2D
- **일정:** 마감 2026-07-22. 기초작업(파트 A + 인터페이스 + 견본)은 7/15까지 리드가 완료 목표.
- **스코프:** 게임잼 빌드. **서브 괴담 1~2개만 구현.** 나머지 구역은 데이터(SO) 복제로 확장 가능하게 설계.
- **팀:** 3인 = 리드 1(경험자) + 초보 2(기초 유니티 코딩 가능, Unity 지식 얕음, 1명은 2023 버전만 사용 경험).
- **문서 깊이:** 파트 A는 상세 기능정의, 파트 B·C는 개요. 미확정 항목(엔딩 전달·저장 모델)은 **인터페이스/데이터로 격리**하여 개발을 막지 않음.

## 1. 핵심 루프 (3계층)

| 계층 | 루프 | 비고 |
|---|---|---|
| **순간** | 이동 → 시야 갱신(손전등+차폐) → 오염도 누적(시간+접촉) → 디버프 반영 | 항상 도는 기본 압력 |
| **구역** | 진입/트리거 → 위협 활성 → 단서 관찰 → 파훼 행동 → 목표물 획득 → 이탈 (실패 시 오염↑/사망 → 리스폰) | **재사용 템플릿** |
| **거대** | 허브(집) → 구역 탐색 → 조각 획득 → 다음 구역 해금 → 엔딩 분기 | 잼에선 1~2 구역으로 축약 |

**구역 템플릿 공통 골격:** `위협 + [수동 규칙] + [능동 도구] + 목표물 + 실패 패널티`. 모든 괴담이 이 5칸의 변주.

## 2. 아키텍처 요약

**4계층 (의존성은 위→아래로만):**

```
Core     : GameManager · EventBus · SceneFlow · SaveSystem(interface)
Systems  : Contamination · Inventory · Dialogue · Audio(FMOD) · Objective · Ending
Player   : Movement · VisionController · ContaminationTarget
Region   : HauntController · Threats · Counters · Interactables · GhostAI
             ▲ 데이터 주입: ScriptableObject (HauntDefinition, ItemDefinition, EndingCondition)
```

**두 가지 설계 원칙:**
- **오염도 = 허브 시스템.** 값이 변하면 이벤트만 쏘고, VisionController·JumpscareDirector·Movement·HUD가 구독. 디버프 단계 추가는 "구독자 추가"로 끝.
- **위협·파훼 = 전략 컴포넌트.** `HauntController`는 흐름(상태기계)만 알고, 무슨 위협/어떻게 깨는지는 갈아끼우는 부품(`IThreatBehavior`, `ICounterCondition`)으로 주입.

**폴더 구조 (`Assets/_Project/Scripts/`):**
```
Core/  Systems/  Player/  Regions/  Threats/  Counters/
Interactables/  AI/  Data/  UI/
```

## 5. 파트 A — 토대 (상세 기능정의)

각 모듈: **책임 / 입력 / 출력·이벤트 / 의존 / 담당·난이도**

### A1. Core — GameManager · EventBus · SceneFlow
- **책임:** 전역 생명주기, 시스템 간 느슨한 통신(이벤트 버스), 씬 전환.
- **출력·이벤트:** 게임 상태 변경 이벤트 발행.
- **의존:** 없음 (최하위).
- **담당/난이도:** 리드 / 중.

### A2. Input (New Input System)
- **책임:** 액션맵 3종(Gameplay/UI/Dialogue) 정의 및 상황별 스위칭.
- **출력:** 이동 벡터, 상호작용/던지기/인벤토리/일시정지 액션 이벤트.
- **의존:** Core.
- **담당/난이도:** 리드 / 중.

### A3. PlayerMovement
- **책임:** WASD 탑뷰 이동. Rigidbody2D 기반, 벽 충돌.
- **입력:** Input 이동 벡터. **출력:** 위치 변경, (오염 3단계 시)속도 감소 반영.
- **설정:** Gravity Scale 0, Freeze Rotation Z, Collision Continuous.
- **의존:** Core, Input.
- **담당/난이도:** 리드 / 하.

### A4. VisionController
- **책임:** 전방 손전등 부채꼴 조준(마우스/이동방향), Light2D 회전.
- **입력:** 조준 방향, 오염도 값(1단계 시 시야 반경 축소).
- **의존:** Player, Contamination(구독).
- **담당/난이도:** 리드 / 상 (Light2D·ShadowCaster 세팅).

### A5. ContaminationSystem  ★허브
- **책임:** 오염도 0~100 관리. 시간 누적 + 접촉 데미지. 단계별 이벤트 발행(1:시야 / 2:환각 / 3:속도·외관, 100:사망).
- **입력:** 시간, 접촉 데미지 이벤트. **출력:** `OnContaminationChanged(float)`, `OnStageChanged(int)`.
- **의존:** Core. **구독자:** Vision, JumpscareDirector, Movement, HUD, Audio.
- **담당/난이도:** 리드 / 중.

### A6. Effects — 안개·화면왜곡·비네트
- **책임:** 대기 안개(Particle), 전체 왜곡(Full Screen Pass 셰이더), 비네트/색보정(Volume). 오염도 값으로 강도 구동.
- **입력:** 오염도(전역 셰이더 프로퍼티 `_Contamination` 또는 Volume weight), 구역.
- **의존:** Contamination(구독).
- **담당/난이도:** 리드 / 상 (Shader Graph·Full Screen Pass).

### A7. AudioManager (FMOD 브리지)
- **책임:** 뱅크 로드, 리스너 부착, 원샷/루프 인스턴스, 전역 파라미터 주입, 오디오 차폐(리스너↔이미터 레이캐스트 → `Occlusion`), 스냅샷 전환.
- **인터페이스:** `IAudioService` (§6). 게임 코드는 이 인터페이스만 호출.
- **의존:** Core. FMOD 오써링은 **리드가 별도 진행**.
- **담당/난이도:** 리드 / 상.

### A8. HUD
- **책임:** 오염도 게이지(상시 or 토글), 상호작용 프롬프트, 인벤토리 슬롯 요약, 목표 현황.
- **주의:** 화면 흐림/비네트는 HUD가 아니라 **Effects(A6)** 담당. HUD는 숫자·바만.
- **의존:** Contamination, Inventory, Objective (구독).
- **담당/난이도:** 초보 2 / 하.

## 6. 인터페이스 계약 (이음새) — 초보 안전벨트

> 리드가 **시그니처만** 먼저 확정(구현 없음). 초보는 이 계약 뒤를 채움. 구현 세부는 파트 B·C 착수 시.

**게임플레이 seam**
- `IThreatBehavior` — `Activate()`, `Tick()`, `Neutralize()`, `bool IsNeutralized`
- `ICounterCondition` — `bool IsSatisfied` (규칙 준수/도구 사용/은신창 판정)
- `IInteractable` — `void Interact(PlayerContext)`, `string Prompt`
- `IThrowable` — `void ThrowTo(Vector2 target)`

**시스템 seam**
- `IInventory` — `Add/Remove/Has(itemId)`, `Combine(a, b)`, 이벤트 `OnChanged`
- `IObjective` — `SetFlag(id)`, `bool HasFlag(id)`, 이벤트 `OnFlagChanged`
- `IEndingCondition` (SO) — `bool Evaluate(objectiveState)` → **엔딩 전달 방식은 여기 데이터로 결정(회의 후)**
- `ISaveModel` — `SaveProgress()`, `RestoreOnDeath()`, `GetCheckpoint()` → **사망/저장 모델은 여기 구현체만 교체(회의 후)**
- `IAudioService` — `PlayOneShot(event,pos)`, `Loop(event)`, `SetParam(name,value)`, `SetSnapshot(name)`

**EventBus 주요 이벤트**
`OnContaminationChanged`, `OnStageChanged`, `OnNoiseEmitted(pos,radius)`, `OnPlayerContact(threat)`, `OnObjectiveFlag`, `OnRegionEnter/Exit`, `OnPlayerDeath`.

## 7. 구역 템플릿 & 수직 슬라이스 (갯벌 견본)

**HauntController 상태기계:**
```
Dormant → Triggered → Threatened → Countered → Objective → Cleared
                          ↳ 규칙 위반/실패 → 오염↑ or 사망
```

**갯벌 매핑 (견본):**
| 칸 | 갯벌 구현 |
|---|---|
| 위협 | `LureVoice` — 진입+안개 시 아이들 목소리 |
| 수동 규칙 | 선택지에서 **[대답하지 않는다]** (`RuleWatcher`) |
| 능동 도구 | 조개껍데기 공기돌 **던져 시선 분산** (`Throwable`+`Distraction`) |
| 목표물 | 갯벌 통과 / 조각 획득 |
| 실패 패널티 | 대답·접근 시 갯벌에 묶여 사망 |

> **이 견본 1개가 완성되면**, 두 번째 괴담(예: 양식장)은 **HauntDefinition SO + Threat 변종 1개**로 대부분 복제됨. → 초보의 일이 "복사 후 값 변경"이 됨.

## 10. 오디오 계약 (FMOD) — 리드 오써링용

**전역 파라미터 (코드가 값 주입):**
| 파라미터 | 범위 | 시점 |
|---|---|---|
| `Contamination` | 0–100 | 오염도 변화 |
| `Region` | 라벨(갯벌/양식장/…) | 구역 진입 |
| `ThreatState` | 0평온/1경계/2추격 | AI 상태 |
| `Occlusion` | 0–1(이벤트별) | 매 프레임 벽 레이캐스트 |

**이벤트:** `player/footstep(Surface)`·`breath`·`throw`·`pickup`, `amb/{region}`, `threat/mudflat_children`·`facefish`·…, `ui/dialogue_blip`·`contamination_stage`, `sting/death`, `music/tension`·`ending_{normal|true|bad}`.
**스냅샷:** Occlusion, 구역 리버브, ContaminationHaze, Death.
**버스:** `Master → Music/SFX/Ambience/Voice/UI`.
