# 🧭 장곡리 코드 해설서

> 현재 구현된 코드 전체를 설명하는 문서입니다. 새로 합류한 사람이 이것만 읽고 코드를 쓸 수 있는 것이 목표.
> 노션에 그대로 붙여넣어도 됩니다. (2026-07-15 기준, Scripts 폴더 36개 파일)

---

## 1. 한눈에 보기

### 폴더 구조

```
Assets/Scripts/
├─ Core/           게임의 뼈대. 아무것도 의존하지 않음
│   ├─ EventBus, GameManager, SceneFlow
│   └─ Interfaces/ (IThreatBehavior, ICounterCondition, IInteractable, IInventory, IObjective, ISaveModel)
├─ Systems/        전역 시스템 (오염도, 대화, 인벤토리, 엔딩, 타이머 …)
├─ Player/         플레이어 (이동, 방향, 줍기, 오염 피격)
├─ Region/         구역(괴담) 진행 엔진 (HauntController, ExitTrigger)
├─ Counters/       "페이즈를 어떻게 깨는가" 부품들
├─ Threats/        "무엇이 위협하는가" 부품들
├─ Sounds/         FMOD 사운드 (SoundManager, 발소리, 리버브)
└─ Data/           ScriptableObject 정의 (아이템, 괴담, 엔딩 조건)
```

### 의존 방향 (중요)

```
Region/Threats/Counters  ──┐
Player                     ├──>  Systems  ──>  Core(EventBus)
Sounds                   ──┘
```

위쪽은 아래쪽을 직접 불러도 되지만, **아래쪽이 위쪽에게 알릴 때는 반드시 EventBus 이벤트로만** 알립니다.
예: `ContaminationSystem`은 `PlayerMovement`가 누군지 모릅니다. 그냥 "오염도 바뀜!"이라고 방송할 뿐이고, PlayerMovement가 알아서 구독해서 듣습니다.

## 2. 꼭 알아야 할 핵심 규칙 4가지

> 💡 코드 작성 전에 이 섹션만은 반드시 읽어주세요.

### ① 시스템 간 통신은 EventBus로

```csharp
// 방송하기 (Raise 함수만 사용!)
EventBus.RaiseNoiseEmitted(position, radius);

// 구독하기 — OnEnable에서 걸고, OnDisable에서 반드시 해제
void OnEnable()  => EventBus.OnNoiseEmitted += HandleNoise;
void OnDisable() => EventBus.OnNoiseEmitted -= HandleNoise;
```

- `event` 키워드 때문에 밖에서 직접 `Invoke()` 불가능 → 반드시 `Raise~` 함수로 발행
- **OnDisable 해제를 빼먹으면** 파괴된 오브젝트가 계속 이벤트를 받아서 에러 납니다

### ② 오염도는 0~1 스케일

- 오염도 관련 모든 수치는 **0~1** 사이입니다. "2%"를 넣고 싶으면 `0.02`
- 인스펙터에 값 넣을 때 특히 주의 (2 를 넣으면 즉사 게임이 됩니다)

### ③ 사운드는 SoundManager 경유

```csharp
SoundManager.Instance.PlayOneShot(eventRef, position);   // 효과음
SoundManager.Instance.SetGlobalParam("RoomSize", 0.5f);  // FMOD 파라미터
```

- FMOD API를 직접 호출하지 마세요. 전부 `SoundManager`를 통해서만
- FMOD 이벤트 필드는 `[SerializeField] EventReference xxx`로 노출하면 인스펙터에서 지정 가능

### ④ 소음 = 게임플레이 신호

"소리를 낸다"는 행동(던지기, 발전기, 뛰기 등)은 전부 이 한 줄입니다:

```csharp
EventBus.RaiseNoiseEmitted(위치, 반경);
```

**누가 반응할지는 던지는 쪽이 몰라도 됩니다.** 듣는 쪽(귀신 카운터, 인면어)이 각자 "내 반경 안인가?"를 판단합니다. 새 소음원을 만들 때도 이 한 줄이면 끝.

## 3. Core — 게임의 뼈대

### 📄 EventBus (static class)

모든 시스템이 서로를 모른 채 대화하는 **공용 게시판**.

| 이벤트 | 언제 발행되나 | 누가 듣나 |
|---|---|---|
| `OnContaminationChanged(float)` | 오염도 값이 바뀔 때마다 (0~1) | 연출(안개), HUD, 사운드 |
| `OnContaminationStageChanged(int)` | 단계(0/1/2/3)가 바뀔 때만 | 이동속도, 점프스케어, 시야 |
| `OnHauntPhaseAdvanced(string, int)` | 괴담이 다음 페이즈로 넘어갈 때 | HUD, 사운드 |
| `OnHauntCleared(string)` | 괴담 최종 클리어 | 목표 시스템 |
| `OnThreatStateChanged(string, int)` | 몬스터 경계 상태 변화 (0평온/1경계/2추격) | FMOD 긴장 음악 |
| `OnNoiseEmitted(Vector2, float)` | 소음 발생 (위치, 반경) | 귀신 카운터, 인면어 |
| `OnObjectiveFlagSet(string)` | 목표 달성 | HUD, 엔딩 |
| `OnPlayerDeath()` | 사망 | GameManager, RestartSaveModel |

### 📄 GameManager

전역 상태(`Playing / Paused / Dead / Ending`) 관리.

- 사망 이벤트 받으면 `Dead`로 전환
- **씬이 로드되면 자동으로 `Playing`으로 복구** (`SceneManager.sceneLoaded` 구독) — 죽고 재시작해도 게임이 멈춰있지 않게
- `Pause()` / `Resume()`은 `Time.timeScale`까지 함께 조절

### 📄 SceneFlow

씬 전환 담당. `FadeAndLoad("씬이름")` 부르면 어두워졌다가 → 로드 → 밝아짐.
페이드는 `unscaledDeltaTime`을 써서 일시정지 중에도 동작.

### 📄 Interfaces/ — 부품 규격 6종

| 인터페이스 | 의미 | 구현하는 것 |
|---|---|---|
| `IThreatBehavior` | "위협은 어떻게 행동하나" | LureVoice(완성), Gaze/인면어(팀원1) |
| `ICounterCondition` | "페이즈는 어떻게 깨나" | DistractionCounter, RuleWatcher |
| `IInteractable` | "E키로 뭘 하나" | Pickup(완성), 발전기(팀원1), 조개던지기(팀원2) |
| `IInventory` / `IObjective` | 인벤·목표 규격 | InventorySystem, ObjectiveSystem |
| `ISaveModel` | 사망 시 처리 규격 | RestartSaveModel (처음으로 리셋) |

> 💡 **왜 인터페이스로 나눴나?** `HauntController`는 "위협이 뭔지" 몰라도 돌아갑니다. 새 위협/파훼법을 만들 때 엔진 수정 없이 부품만 꽂으면 되도록.

## 4. Systems — 전역 시스템

### 📄 ContaminationSystem ⭐ (이 게임의 허브)

오염도 값 하나(0~1)를 관리하고, 바뀔 때마다 방송하는 시스템.

- `Add(amount)` — 오염도 증감의 **유일한 창구**. 음수도 허용(정화 아이템 대비)
- 시간이 지나면 자동으로 조금씩 상승 (`passiveGainPerSecond = 0.001` = 초당 0.1%)
- 단계 임계값: **0.3 / 0.6 / 0.9** → 넘을 때 `OnContaminationStageChanged` 방송
- **1.0 도달 = 사망 이벤트 발행**

> 💡 오염도로 뭔가 하고 싶으면 이 클래스를 고치지 말고, **이벤트를 구독**하세요. (예: 3단계에 이동 느려지는 것도 PlayerMovement가 구독으로 처리)

### 📄 DeadlineTimer

재사용 카운트다운. `StartTimer(초)` → 매 프레임 `OnTick(남은시간)` → 끝나면 `OnExpired`.
"시간이 다 되면 무엇이 벌어질지"는 타이머가 모릅니다 — 쓰는 쪽이 콜백에서 결정.
(갯벌 밀물 = OnTick에서 오염도 증가 / 양식장 탈출 = OnExpired에서 실패)

### 📄 DialogueSystem

대화 **요청 창구**. 화면을 직접 그리지 않고, UI가 구독할 이벤트만 쏩니다.

| 함수 | 용도 |
|---|---|
| `Show("대사")` | 단순 대사 한 줄 |
| `ShowChoice(선택지배열, 콜백)` | 선택지. 콜백에 선택된 index가 옴 |
| `ShowRapidPrompt(제한시간, 성공콜백, 실패콜백)` | 갯벌 3페이즈 연속 팝업 — 제한시간 내 캔슬하면 성공 |

> ⚠️ `DialogueUI`(실제 화면 그리는 쪽)는 아직 미구현. UI가 이 세 이벤트(`OnShowLine`, `OnShowChoice`, `OnShowRapidPrompt`)를 구독해서 그리면 됩니다.

### 📄 InventorySystem

- **열쇠템**(영구, 중복 불가)과 **소모품**(개수 스택) 분리 보관
- `Has / Add / Remove(itemId)` + `Combine(a, b, out result)` (레시피는 ItemDefinition에 정의)
- 내용 바뀌면 `OnChanged` 이벤트 → InventoryUI가 구독 예정

### 📄 ObjectiveSystem

클리어 플래그 저장소. `SetFlag("mudflat_clear")` / `HasFlag(id)`.
**on/off만 저장**합니다. "몇 개 중 몇 개"는 저장하지 않고 필요한 쪽이 플래그를 세서 계산.

### 📄 EndingEvaluator + EndingCondition(SO)

엔딩 판정. `Evaluate()`가 EndingCondition들을 우선순위 순서로 검사해서 첫 번째 만족하는 엔딩(True/Normal/Bad) 반환. 조건은 SO라서 **코드 수정 없이 인스펙터에서 플래그 조합만 바꾸면 됨.**

### 📄 RestartSaveModel

회의 결정 반영: **사망하면 처음 씬으로.** `OnPlayerDeath` 받으면 `FadeAndLoad(시작씬)`. 끝.

### 📄 LitVisibility

**"손전등 밖 몬스터는 안 보인다"** (다크우드 스타일). 몬스터에 붙이는 컴포넌트.

- 매 프레임: 플레이어 시야콘(각도+거리+벽차폐) 또는 발밑 보조광 안에 있는지 판정
- 안이면 알파 1로 페이드 인, 밖이면 0으로 페이드 아웃
- ⚠️ **렌더링만 숨깁니다. AI는 계속 돌아갑니다** — "안 보이는데 소리는 다가온다"가 의도된 공포 연출

### 📄 CameraMovement

플레이어를 Lerp로 부드럽게 따라가는 카메라. z는 -10 고정.

## 5. Player — 플레이어

| 파일 | 역할 | 핵심 |
|---|---|---|
| `PlayerMovement` | WASD 이동 | Rigidbody2D 물리 이동. 대각선 속도 보정(normalized). **오염 3단계 이벤트 구독 → 속도 70%로** |
| `PlayerFacing` | 몸 좌우 반전 | 마우스가 왼쪽이면 flipX. ⚠️ **localScale 반전 금지** — 자식 손전등까지 뒤집힘 |
| `VisionAim` | 손전등 조준 | 마우스 방향으로 Spot Light 회전 (-90° 보정: Light2D는 +Y가 정면) |
| `ContaminationTarget` | 위협 피격 | 위협 콜라이더 접촉 → `ThreatContact` 정보 읽어 오염 증가 or 즉사 |
| `Pickup` | 아이템 줍기 | E키 상호작용 → 인벤 추가 + 목표 플래그 + (목표물이면) 구역 클리어 처리 |

> 💡 위협 오브젝트 만들 때: 위협 쪽에 `ThreatContact` 붙이고 `contaminationAmount`(0~1)와 `killInstantly`만 설정하면 피격 처리는 자동입니다.

## 6. Region — 구역(괴담) 진행 엔진 ⭐⭐

### 📄 HauntController — 이 게임의 심장

한 구역(갯벌, 양식장)의 진행을 관리하는 **페이즈 반복 상태기계**.

```
Dormant ──Trigger()──> Threatened(페이즈0)
   위협 활성 + 파훼조건 폴링
   조건 전부 만족 ──> Countered ──> 다음 페이즈 있으면 Threatened(페이즈+1)
                                └─> 없으면 ObjectiveReady
ObjectiveReady ──CompleteHaunt()──> Cleared (방송: OnHauntCleared)
```

- **페이즈(HauntPhase)는 인스펙터에서 조립**: 위협 배열 + 파훼조건 배열 + 데드라인 옵션
- `Update()`가 매 프레임: 위협들 `Tick()` 호출 + 파훼조건 전부 `IsSatisfied`인지 폴링
- `Fail(이유)`: `Caught`(즉사) 또는 그 외(오염도 +0.25 후 계속)
- 데드라인 페이즈면 타이머 자동 가동, 밀물처럼 지속 피해도 옵션으로

> 💡 **새 페이즈를 추가하는 데 코드가 필요 없습니다.** 인스펙터에서 phases 배열에 한 칸 추가하고 부품을 꽂으면 끝. 이게 이 구조의 핵심 목적.

> ⚙️ 인터페이스 배열은 인스펙터 직렬화가 안 되므로 `MonoBehaviour[]`로 받고 런타임에 캐스팅합니다. **위협/카운터가 아닌 컴포넌트를 꽂으면 조용히 무시되니 주의.**

### 📄 ExitTrigger

구역 출구에 놓는 트리거. 플레이어가 닿으면 `CompleteHaunt()` 호출.
`ObjectiveReady` 전에는 내부 가드 때문에 그냥 통과되는 문 — **모든 페이즈를 깬 뒤에만** 작동.

## 7. Counters — "어떻게 깨는가" 부품들

| 파일 | 규칙 | 사용처 |
|---|---|---|
| `DistractionCounter` | "내 반경(hearRadius) 안에서 소음이 N번(requiredCount) 나면 만족" | 갯벌: 귀신마다 붙임. 조개껍데기가 근처에 떨어질 때마다 카운트 |
| `RuleWatcher` | 만족/위반을 밖에서 알려주는 그릇. `MarkSatisfied()` = 파훼 진행, `MarkViolated()` = 즉시 Fail | 갯벌: "[대답하지 않는다]" 선택 결과를 LureVoice가 알려줌 |
| `Concealment` | 존 안에 플레이어가 있으면 `IsPlayerConcealed = true` (static — 어느 존이든 하나라도 숨어있으면 true) | 양식장: 상자 뒤 숨기. 인면어 AI가 이 값 체크 |

> 💡 `DistractionCounter`는 **소음을 어디서 냈는지만** 봅니다. 던진 게 조개든 발전기 소리든 상관없음 — 소음이면 다 반응. (§2-④ 참고)

## 8. Threats — "무엇이 위협하나" 부품들

### 📄 LureVoice (갯벌 아이들) — 완성, 팀원1의 참고 원본

정지형 위협(돌아다니지 않음). `Activate()`되면:

- **일반 모드**: 선택지 표시 → 0번([대답하지 않는다]) 선택 시 `rule.MarkSatisfied()`, 대답하면 즉사
- **RapidPrompt 모드** (`useRapidPrompt=true`, 3페이즈용): 연속 팝업 — 제한시간 내 캔슬 못하면 위반

> 💡 갯벌 2·3페이즈는 이 클래스를 **복제/설정 변경**으로 만들면 됩니다. 새 위협(인면어)도 같은 `IThreatBehavior` 규격으로.

### 📄 ThreatContact

위협 오브젝트에 붙이는 **데이터 태그** (로직 없음). 오염량(0~1), 즉사 여부만 들고 있으면 `ContaminationTarget`이 알아서 읽습니다.

## 9. Sounds — FMOD

| 파일 | 역할 |
|---|---|
| `SoundManager` | FMOD 브리지. 원샷/루프 재생, 전역 파라미터(Contamination·Region·ThreatState·RoomSize), 인스턴스 파라미터(Occlusion), 스냅샷. **모든 사운드 호출은 여기를 경유** |
| `FootstepSurface` | 발밑 바닥 레이어 판정 → 재질별 발소리 이벤트 재생 (Wood/Stone/Mud/Gravel/Leaves) |
| `RoomsizeEstimator` | 8방향 레이캐스트로 벽까지 평균거리 측정 → 좁을수록 리버브 강해지는 `RoomSize` 파라미터 전송 (0.2초 간격) |

> ⚠️ FMOD 파라미터 스코프 주의: `RoomSize` 등 전역 파라미터는 FMOD Studio에서 **Global**로, `Occlusion`은 **Local**로 만들어야 합니다. 반대로 만들면 에러 없이 조용히 무시됩니다.

## 10. Data — ScriptableObject

| SO | 필드 | 만드는 법 |
|---|---|---|
| `ItemDefinition` | itemId, 이름, 아이콘, 열쇠템 여부, 조합 레시피(파트너id → 결과id) | Project 우클릭 → Create → Janggok |
| `HauntDefinition` | huntId, regionLabel(FMOD Region 파라미터용) | 〃 |
| `EndingCondition` | 엔딩 타입, 우선순위, 필요 플래그 배열 | 〃 |

> ⚙️ **왜 페이즈가 HauntDefinition(SO)에 없나?** SO는 씬 오브젝트를 참조할 수 없어서. 페이즈 배열(위협·카운터 참조 포함)은 씬에 있는 `HauntController`가 들고 있습니다.

## 11. 실전 예시 — 갯벌 1페이즈가 처음부터 끝까지 흐르는 과정

1. 플레이어가 갯벌 입구 트리거 진입 → 입구 스크립트가 `hauntController.Trigger()` 호출
2. `HauntController`: 페이즈0의 `LureVoice.Activate()` 실행
3. `LureVoice` → `DialogueSystem.ShowChoice(["[대답하지 않는다]", "대답한다"], 콜백)`
4. (미래의) `DialogueUI`가 선택지를 화면에 그림 → 플레이어가 0번 클릭 → 콜백 실행
5. 콜백이 `rule.MarkSatisfied()` → `RuleWatcher.IsSatisfied = true`
6. 플레이어가 조개껍데기 던짐 → `EventBus.RaiseNoiseEmitted(위치, 반경)`
7. 귀신의 `DistractionCounter`: 반경 안이면 count++ → `IsSatisfied = true`
8. `HauntController.Update()`: 카운터 전부 만족 감지 → `MarkCountered()` → 다음 페이즈로
9. (마지막 페이즈였다면) `ObjectiveReady` → 플레이어가 출구 `ExitTrigger` 밟음 → `CompleteHaunt()` → `OnHauntCleared("mudflat")` 방송
10. `ObjectiveSystem`이 플래그 저장 → 나중에 `EndingEvaluator`가 이 플래그로 엔딩 판정
