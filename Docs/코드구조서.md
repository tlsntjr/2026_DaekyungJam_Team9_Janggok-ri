## 1. 레이어 개요

```
Core      : 아무것도 의존 안 함 — EventBus, GameManager, SceneFlow
Systems   : Core만 의존 — Contamination, Audio, Inventory, Objective, Dialogue, Ending, DeadlineTimer
Player    : Core+Systems 의존 — Movement, Facing, VisionConeAim, Footstep, RoomSize, ContaminationTarget, (Stamina*)
Region    : 전부 의존, 데이터(SO)로 조립 — HauntController, Threats, Counters, Interactables, GhostAI
UI        : Systems 이벤트 구독만 — HUD, Dialogue UI, Inventory UI, Jumpscare, Menu
```//`*` = 조건부(구역 선택에 따라 필요 여부 결정, §11 참조)

**통신 원칙:** 상위 레이어는 하위 레이어를 직접 참조하지만, **역방향은 항상 이벤트(EventBus)로만.** 예: `ContaminationSystem`은 `VisionConeAim`을 모름 — 값이 바뀌면 이벤트만 쏘고, Vision이 구독.

## 6. Region — 이번 세션의 핵심 변경

### 6-1. 왜 바뀌었나

레벨 설계 문서를 보면 갯벌·양식장 모두 **"위협 활성 → 파훼 → 다음 발판"이 페이즈마다 강도만 세지며 반복**됩니다. 기존 `HauntController`(§7)는 **한 번만 도는 6단계 상태기계**였는데, 이걸 갈아엎지 않고 **그 상태기계를 페이즈 개수만큼 감싸는 루프**로 확장합니다.

### 6-2. 상태 흐름 (갱신)

```
Dormant
  → Triggered (페이즈[0] 시작)
      → Threatened  (해당 페이즈의 Threat[] 활성화)
      → Countered   (해당 페이즈의 Counter 조건 전부 충족)
      → 다음 페이즈 있으면 → Threatened로 복귀 (페이즈 인덱스 +1)
      → 다음 페이즈 없으면 → ObjectiveReady
  → Cleared (목표물 획득 + 이탈)

실패(규칙 위반 / 데드라인 초과) → 오염↑ 또는 즉사, 페이즈는 유지(재시도) or 사망 처리
```

**지난번 만든 스켈레톤(`HauntState` enum, `Trigger/ActivateThreat/MarkCountered/Clear`)은 그대로 재사용**하고, 그 위에 **페이즈 인덱스 진행 로직만 추가**합니다. 새로 갈아엎는 게 아니라 감싸는 구조라 초보1이 이미 시작했다면 작업 손실 없습니다.

### 6-3. 데이터 (SO)

```
HauntDefinition (SO)
  ├ id, 지역명
  ├ HauntPhase[] phases        ← 신규: 페이즈 배열
  └ (해금 조건 등 기존 필드)

HauntPhase (SO 또는 직렬화 클래스)
  ├ IThreatBehavior[] threats        ← 이 페이즈에서 활성화될 위협들 (갯벌 2페는 2마리)
  ├ ICounterCondition[] counters     ← 전부 충족해야 Countered
  ├ int requiredDistractionCount     ← "3번 나눠 던지기" 같은 반복 요구치
  ├ float safeWindowDuration         ← 분산 성공 시 이동 가능 시간
  └ DeadlineTimer? deadline          ← 선택: 밀물처럼 시간 압박이 있는 페이즈만
```

### 6-4. 인터페이스

| 인터페이스 | 멤버 | 구현체 | 비고 |
|---|---|---|---|
| `IThreatBehavior` | `Activate()`, `Tick()`, `Neutralize()`, `IsNeutralized` **+ 신규** `SetProgress(float t)` | `LureVoice`(갯벌 아이들), `Gaze`(인면어), `BehindStalker`(등대 여인), `Chaser`(등대 추적자) | `SetProgress`는 등대처럼 "올라갈수록 강해짐"에 사용 — 층수/진행률(0~1)을 넣으면 속도·템포 커브 반영 |
| `ICounterCondition` | `IsSatisfied` | `RuleWatcher`(대답 안 함 / 조명 시 정지), `DistractionZone`(어그로 분산 — 신규 통합), `Concealment`(은신 — 신규 통합), `ToolCombine`(기름통+조명탄) | 아래 6-5 참고 |
| `IInteractable` | `Prompt`, `Interact()` | `Throwable`(조개껍데기), `Generator`(발전기 — 조건부로 `IMinigame` 래핑), `Pickup`, `CombineStation` | |
| `IMinigame` (조건부, 신규) | `StartOrResume()`, `Interrupt()`, `bool IsComplete` | 양식장 채택 시만 구현 | **인터럽트-재개 상태 보존** 필요 (발전기 가동 중 숨기 인터럽트) |

### 6-5. 새로 통합한 공용 컴포넌트 (레벨 문서에서 발견된 반복 패턴)

| 컴포넌트 | 대체하는 것 | 동작 |
|---|---|---|
| **`DistractionZone`** | 조개껍데기(갯벌) / 발전기 소음(양식장) | "지점 지정 → 대상 Threat의 어그로가 그쪽으로 N초 쏠림" 공용화. `IThreatBehavior.Tick()`이 이 컴포넌트의 활성 여부를 읽어 이동 목표를 바꿈 |
| **`Concealment`** | 벽 틈새(등대) / 상자 뒤(양식장) | 존 안에 있으면 `GhostAI.Perception`의 시각·청각 채널을 무시. 진입/이탈 트리거만 있으면 됨 |

### 6-6. GhostAI

| 항목 | 내용 |
|---|---|
| 기존 상태 | `Patrol → Suspect → Chase → Retreat/Despawn` |
| **신규 상태** | `Berserk` — 양식장 3페(녹음 재생 후 광폭화)처럼 **연출이 강제로 꽂아넣는** 상태 |
| **신규 API** | `ForceState(state, duration)` — 자율 인지가 아니라 스크립트가 강제 전환 |
| **신규 입력** | `SetProgressScale(float t)` — 등대 층수 기반 속도/템포 escalation |
| 인지 3채널 | 시각(각도+거리+차폐) · 청각(`OnNoiseEmitted`) · 접촉(→Contamination) — 기존 유지, `Concealment` 존이 이 채널들을 억제 |
| `LitVisibility` | 다크우드식 "손전등 밖 몬스터는 렌더링 자체 안 함" — 플레이어 시야콘 재사용, 몬스터 SpriteRenderer on/off 게이트 |

### 6-7. `IThreatBehavior` vs `GhostAI`의 관계 (헷갈리기 쉬운 지점)

- **`IThreatBehavior`** = "이 구역의 위협이 **무엇을 트리거로 반응하는가**"(연출/규칙 레이어). 갯벌 아이들처럼 사실상 정지 상태에서 목소리·분산 판정만 하는 **가벼운 위협**엔 이것만으로 충분.
- **`GhostAI`** = "그 위협이 필드를 **실제로 돌아다니는 방식**"(배회·인지·추격 엔진). 등대·양식장처럼 실제로 쫓아오는 위협에 붙음.
- 즉 **모든 위협이 GhostAI를 갖는 게 아닙니다.** `IThreatBehavior`가 뼈대, `GhostAI`는 "쫓아다니는" 위협에만 추가로 붙는 선택적 구성요소입니다.

## 9. 핵심 이벤트 흐름 (예시 2개)

**오염도 변화:**
```
ContaminationTarget(위협 접촉) → ContaminationSystem.Add()
  → EventBus.OnContaminationStageChanged
      ├→ VisionConeAim (시야 반경 축소)
      ├→ Effects (안개/왜곡 강도)
      ├→ AudioManager.SetGlobalParam("Contamination", …)
      ├→ PlayerMovement (속도 배율)
      └→ HUD (게이지 갱신)
```

**구역 페이즈 진행 (갯벌 예):**
```
플레이어 진입 → HauntController.Trigger() → phase[0] Threatened
  → LureVoice.Activate() (질문 창 발생)
  → 플레이어가 RuleWatcher 충족([...] 선택) + DistractionZone 1회 성공
  → 페이즈 조건 충족 → MarkCountered() → 다음 페이즈 있음 → phase[1] Threatened로 복귀
  → … 마지막 페이즈까지 반복 → ObjectiveReady → Cleared
  → EventBus.OnHauntCleared → ObjectiveSystem.SetFlag(huntId)
```

## 10. 이번 세션에서 확정된 핵심 결정 (누적 요약)

- 카메라: **직교 2D + 오블리크 아트 + Y정렬**, 3D 전환 안 함 (Hades 2 레퍼런스)
- 그림자: `ShadowCaster2D`는 오브젝트의 **바닥 발자국** 기준, 실루엣 전체 아님
- 몸 방향: `flipX`(마우스 기준) / 손전등 회전은 완전 독립
- 오디오: FMOD, `AudioManager` 경유 원칙, **Global/Local 파라미터 구분** 엄수
- 발소리: 재질=Unity Layer 기반, 밀폐감=레이캐스트 기반 — **서로 다른 축**
- **HauntController: 단일 패스 → 페이즈 배열 반복 구조로 일반화** (이번 세션 최대 변경)
- `DistractionZone`/`Concealment`를 구역 간 공용 컴포넌트로 통합

## 11. 미확정 / 조건부 (구조엔 자리만 마련)

| 항목 | 영향 범위 |
|---|---|
| 갯벌 3페이즈 vs 단판 | `HauntPhase` 배열 길이=1 vs N — 구조는 이미 양쪽 다 지원 |
| 서브 괴담 최종 1~2개 선택 | 비용 순위: 갯벌(쌈) < 등대(중, 스태미나 필요) < 양식장(비쌈, 미니게임 필요) |
| `PlayerStamina` | 등대 채택 시만 구현 |
| `IMinigame` | 양식장 채택 시만 구현 |
| 발소리 트리거 방식 | 거리 기반(패치 완료) vs Animation Event(권장) — Animator 세팅 여부에 따라 결정 |
| 엔딩 전달 / 저장·사망 모델 | `IEndingCondition`/`ISaveModel` 인터페이스만 고정, 구현은 회의 후 |
